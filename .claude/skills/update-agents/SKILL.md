# Актуализация AGENTS.md

Цель: чтобы `AGENTS.md` в корне проекта точно описывал проект **сейчас**, и другой ассистент
мог продолжить работу, прочитав только его.

## 1. Что изменилось

- `git log --format='%h %ad %s' --date=short` — коммиты после последнего изменения AGENTS.md
  (`git log -1 --format=%h -- AGENTS.md`), и `git diff <тот коммит> --stat`.
- `git status --short` — незакоммиченные работы тоже стоит упомянуть, если они меняют устройство проекта.

## 2. Сверить каждый раздел с реальностью

Проверяй по файлам и командам, а не по памяти:

- **Ссылки и хостинг**: `gh repo view --json url,visibility`, `gh api repos/{owner}/{repo}/pages`
  (домен, https, папка), `docs/CNAME`, `SITE` в `tools/seo.py`.
- **Структура**: `src/`, `tools/`, `backend/`, корневые папки, `.gitignore`. Новые папки или генераторы — описать.
- **Сборка**: шапка `tools/build.py` (что собирается и куда), команда запуска.
- **Страницы**: какие есть в `src/pages/` и `src/data/*/`; правила меню и футера в `src/pages/index.html`.
- **Цены**: `SERVICE_PRICE` в `tools/seo.py`, меню в `index.html`, `src/pages/uslugi.html`.
  Список текущих цен в AGENTS.md должен совпадать.
- **Форма**: объект `FORM` в `src/assets/js/main.js`, состояние `backend/form-handler/`.
- **Не заполнено**: `CONTACTS`, `ANALYTICS` в `main.js` и т. п. — убрать то, что уже заполнено.
- **Правила владельца**: если в разговорах появились новые решения владельца (что делать или не делать
  на сайте) — добавить. Ничего не придумывать.

## 3. Обновить файл

- Правь только устаревшее или недостающее; формат и стиль файла сохраняй.
- Не вписывай секреты: токены, пароли, серверные ключи. Репозиторий публичный.
- Если всё актуально — так и скажи, файл не трогай.

## 4. Отчёт и публикация

- Коротко перечисли владельцу, что поменял и почему.
- Закоммить **только** `AGENTS.md` (и сам этот скилл, если правил его) с сообщением
  `AGENTS.md: актуализация` и запушь в `main`. Чужие незакоммиченные правки не трогай.
